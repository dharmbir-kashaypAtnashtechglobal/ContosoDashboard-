# Data Model: Document Upload and Management

## Entity Overview

This feature extends the existing ContosoDashboard model layer with the following entities.

### Document

| Field | Type | Notes |
|---|---|---|
| DocumentId | int | Primary key, consistent with existing integer-based entity IDs |
| Title | string | Required; user-facing document name |
| Description | string? | Optional metadata |
| Category | string | Required text category such as Project Documents, Personal Files, Reports, Presentations, Team Resources, or Other |
| ProjectId | int? | Optional association to a project |
| TaskId | int? | Optional association to a task |
| UploadedByUserId | int | Reference to the uploader |
| OriginalFileName | string | Original user-provided file name |
| StoredFileName | string | GUID-based file name used for storage safety |
| FilePath | string | Relative or local storage path generated by the storage service |
| ContentType | string | MIME type, including long values for Office documents |
| FileSizeBytes | long | Captured file size |
| UploadedAt | DateTime | Audit timestamp |
| UpdatedAt | DateTime? | Last metadata or file replacement timestamp |
| IsActive | bool | Defaults to true; deleted records are removed rather than soft-deleted |

**Relationships**:
- Many `Document` rows belong to one `User` via `UploadedByUserId`
- Many `Document` rows may belong to one `Project` via `ProjectId`
- Many `Document` rows may belong to one `Task` via `TaskId`
- One `Document` may have many `DocumentShare` rows
- One `Document` may have many `AuditEvent` rows

### DocumentShare

| Field | Type | Notes |
|---|---|---|
| DocumentShareId | int | Primary key |
| DocumentId | int | Document being shared |
| SharedWithUserId | int | Recipient user |
| SharedByUserId | int | User who initiated the share |
| SharedAt | DateTime | Share timestamp |
| Message | string? | Optional note or context |

**Relationships**:
- Many `DocumentShare` rows belong to one `Document`
- Many `DocumentShare` rows belong to one `User` for the recipient and one `User` for the sender

### AuditEvent

| Field | Type | Notes |
|---|---|---|
| AuditEventId | int | Primary key |
| EventType | string | Upload, download, preview, delete, share, replacement |
| DocumentId | int? | Nullable for events that are not tied to a specific document |
| UserId | int | User performing the action |
| ProjectId | int? | Optional project context |
| EventTime | DateTime | Event timestamp |
| Details | string? | Additional metadata or context |

**Relationships**:
- Many `AuditEvent` rows may reference one `Document`
- Many `AuditEvent` rows belong to one `User`
- Many `AuditEvent` rows may reference one `Project`

## Validation Rules

- `Title` is required and should be trimmed before storing.
- `Category` is required and must match one of the supported categories defined in the feature requirements.
- `ContentType` can store long MIME strings and must remain compatible with Office document types.
- `FileSizeBytes` must be greater than zero and no larger than the configured 25 MB limit.
- `StoredFileName` must be unique and derived from a GUID-based identifier to avoid path collisions and traversal issues.
- `ProjectId` may be null for personal documents, but if supplied it must reference an existing project.
- `TaskId` may be null; if provided it must reference an existing task and the task’s project must align with the document’s project context where applicable.
- `DocumentShare` must prevent duplicate share records for the same document and recipient.
- `AuditEvent` should be append-only and retained for reporting requirements.

## State and Lifecycle Notes

- A document starts in an `Uploaded` state after the file is validated and persisted.
- A document can transition to `Shared` when one or more shares are created.
- A document can transition to `Updated` when metadata is modified or the file is replaced.
- A document can transition to `Deleted` only through an explicit delete action; the MVP does not include soft-delete or trash handling.

## Relationship Summary

- `User` 1 → many `Document`
- `User` 1 → many `DocumentShare` (as recipient)
- `User` 1 → many `DocumentShare` (as sender)
- `Project` 1 → many `Document`
- `Task` 1 → many `Document`
- `Document` 1 → many `DocumentShare`
- `Document` 1 → many `AuditEvent`
